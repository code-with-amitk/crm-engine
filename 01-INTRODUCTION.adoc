== Executive Summary

This CRM Backend is a modern, scalable Customer Relationship Management system designed to empower real estate organizations. It manages the complete sales lifecycle—from lead acquisition through deal closure—while providing real-time collaboration features, advanced notification systems, and comprehensive audit trails.

=== Problem Statement

Real estate businesses struggle with:

* **Scattered Information**: Leads tracked across multiple platforms (emails, calls, spreadsheets)
* **Poor Coordination**: Sales teams lack visibility into pipeline and customer interactions
* **Manual Processes**: Time-consuming data entry and follow-up management
* **Scalability Issues**: Legacy systems cannot handle growth without architectural changes
* **Compliance Gaps**: Insufficient audit trails and activity tracking for accountability

=== Solution Approach

The CRM Backend provides:

* **Centralized Lead Management**: Single source of truth for all customer interactions
* **Real-time Collaboration**: Multiple users can work on shared leads and requirements simultaneously
* **Intelligent Follow-up System**: Automated reminders and notifications for timely customer engagement
* **Multi-tenant Architecture**: Support for multiple organizations with complete data isolation
* **Audit & Compliance**: Comprehensive activity logs and tenant subscription management

== Why This CRM Solution?

=== Key Differentiators

==== 1. **Microservices-Ready Architecture**
[source]
----
Traditional Monolith          Modern Service-Oriented
├── API Server      →        ├── Main API (REST)
├── Notifications   →        ├── Notifier Service (Async)
└── Reports         →        └── Parser Service (Async)
----

The system is organized into distinct services that can:
* Scale independently based on load
* Be deployed and updated without downtime
* Use different technology stacks if needed
* Isolate failures to specific components

==== 2. **Built for Real Estate Sales Workflows**

Unlike generic CRM solutions, this backend understands real estate:

* **Property Requirements**: Area, budget, facing, society, vastu, floor, prefereed society, property type(flat/plot etc), purpose(investment/self use)
* **Lead Stages**: New → Interested → Negotiating → Closed
* **Channel Partners**: Track commissions and collaboration
* **Site Visits**: Coordinate attendance and follow-ups
* **Compliance**: Tenant-level subscription management and enforced access control

==== 3. **Mobile-First Design**

* JWT-based stateless authentication for native mobile apps
* Expo Push Notifications for real-time alerts
* Optimized endpoints for bandwidth-constrained environments
* Offline-capable token refresh mechanism

==== 4. **Enterprise-Grade Security**

* Role-based access control (Owner vs. Employee)
* Multi-factor tenant isolation with subscription validation
* Rate limiting to prevent abuse
* SSL/TLS encryption in transit
* Bcrypt password hashing with configurable cost
* Refresh token rotation with SHA-256 hashing

==== 5. **Developer-Friendly**

* Clear separation of concerns (routing, middleware, business logic, data access)
* Structured JSON logging for easy debugging
* Comprehensive error handling with user-friendly messages
* Well-documented API with consistent response formats
* Environment-based configuration

== System Characteristics

=== Reliability & Uptime

* **Target SLA**: 99.5% uptime for production deployments
* **Connection Pooling**: Reuses database connections efficiently
* **Health Checks**: Continuous liveness and readiness probes
* **Graceful Shutdown**: Drains in-flight requests before terminating
* **Automatic Retries**: Transient failures are retried automatically

=== Scalability

* **Horizontal Scaling**: Add more instances behind load balancer
* **Stateless Design**: No sticky sessions or server-local state
* **Database Optimization**: Indexes on frequently queried columns
* **Connection Limits**: Configurable pool size to prevent resource exhaustion

=== Security

* **Defense in Depth**: Multiple security layers (API, middleware, database)
* **Input Validation**: All user inputs sanitized
* **Authorization Checks**: Every endpoint validates permissions
* **Encrypted Passwords**: Bcrypt with salt
* **Token Security**: Short-lived access tokens + refresh rotation

=== Observability

* **Structured Logging**: JSON logs for easy parsing and analysis
* **Request Tracing**: Request IDs for tracking through systems
* **Error Tracking**: Detailed error messages with context
* **Performance Metrics**: Response times and throughput monitoring

== Technology Decisions & Rationale

=== Why Go?

* **Performance**: Excellent throughput, low latency, fast startup
* **Concurrency**: Goroutines handle thousands of concurrent connections
* **Deployment**: Single binary, no runtime dependencies
* **Production-Ready**: Used by Docker, Kubernetes, Grafana, etc.
* **Team Expertise**: Growing adoption in modern backend development

=== Why PostgreSQL?

* **ACID Transactions**: Guarantees data consistency
* **Advanced Features**: JSON support, partial indexes, CTEs for complex queries
* **Reliability**: Trusted by financial systems and mission-critical apps
* **Scaling**: Table partitioning and replication strategies available
* **Open Source**: No vendor lock-in, active community

=== Why Docker?

* **Consistency**: Identical environment from dev to production
* **Isolation**: Services don't interfere with each other
* **Reproducibility**: Same image runs everywhere
* **Orchestration**: Works with Kubernetes, Docker Swarm, or managed services
* **Efficiency**: Lightweight compared to VMs
